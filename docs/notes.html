What this project is

An interactive family tree of programming languages, inspired by musicmap.info. You click a language and see where it came from, how it works, and what its code looks like. The goal is to help beginners learn the history and basics of computer science, and to present it at conferences.

What we've decided so far

  • The map is about programming languages, grouped by lineage (which language grew out of which).
  • Start with just the ALGOL family in pink: ALGOL, Pascal, C, C++, Java, C#, Go, Rust. Other families (Lisp, Fortran, Smalltalk, ML, Python) come later.
  • The page is just the tree: no title and no explanations. It's shaped like a tree, oldest at the top, with a timeline down the left side.
  • Zoom in (scroll, pinch, or the + button) to a language and four lesson bubbles appear: types, if/else, loops, functions.
  • Lessons are interactive with very few words: step through a loop, change a function's inputs, slide an age to flip an if/else, tap a value to see its type. The same lesson can be switched between languages to compare.
  • Each language has a parent (its main ancestor). Other influences come later.
  • Audience: beginner learners. Tone: simple, friendly, dark and glowy with cute pink.
  • Built in Python, which makes a static website that can live on GitHub Pages.

Questions for the professor

  1. What is the research question? Is this a teaching tool we test with students, a way to organize the history of languages, or both?
  2. Mixed ancestry: Python grew from ABC and borrowed ideas from ALGOL-style languages and Lisp. Should every language get one main parent plus extra "influence" links, or should we allow several parents?
  3. Which languages next? How should we choose the next 20: most popular, most important historically, or most useful for teaching?
  4. Are these placements fair? For example, Rust under C++, Java under C++, and Haskell in an "ML" family of its own.
  5. Sources: Where should the facts (years, creators, influences) come from, so we can cite them at a conference?
  6. The notesheet: What should go on it, and should it be a page on this site or a separate handout?
  7. Testing with students: If we try it with a class, do we need any approval first?

Next steps

  1. Talk to the professor and settle the questions above.
  2. Fix any placements he disagrees with, then add the influence links (for example, Smalltalk → Java).
  3. Add the next family (each one gets its own color) and grow to about 30 languages, with sources for each fact.
  4. Add more lessons: while loops, arrays, strings, and a "what does this print?" challenge.
  5. Show ALGOL-family facts when zooming: who made it, and why.
  6. Try it with a few real beginners and note where they get confused.

What could be made from this project

  • A free learning site for students: explore the history of programming at their own pace.
  • A quiz mode: "Which language came first?" and "Match the language to its big idea."
  • Compare two languages side by side (same task, different code).
  • Paradigm filters: highlight everything functional, or everything object-oriented.
  • A printable poster or class handout made from the same data.
  • A conference paper or demo about how a visual family tree helps beginners learn.
  • An open dataset of language lineage that other teachers can reuse.
  • Other maps later: operating systems, databases, or algorithms, using the same engine.
